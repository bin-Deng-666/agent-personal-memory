# 记忆质量与评估

个人记忆应当能独立于一次具体任务使用，帮助理解用户或给出合适建议。这个要求不等于避开当前对话的话题：写作、学习、工作、投资、家庭和生活尝试中都可能出现有价值的个人信息。

## 收录边界

| 场景       | 不直接保存的任务内容                 | 可以保存的个人意义                           |
| ---------- | ------------------------------------ | -------------------------------------------- |
| 写作       | 这篇文章八百字、三段、加引语         | 用户写给读者时倾向先举例再解释概念           |
| 学习       | 某份作业的题号与格式                 | 实际尝试课程的经历，先小规模试用再投入的倾向 |
| 职业选择   | 某个项目先改哪个模块                 | 转行探索、投入时间、家庭支出等约束           |
| 家庭与生活 | 这次旅行调整行程顺序                 | 照护责任、重要事件、学车等实际尝试与自述感受 |
| 软件工作   | 文件、参数、开发排期、安装与发布配置 | 原话支持的验证、复用等有适用范围的原则       |
| 投资研究   | 某次数据更新计划和回测指标           | 用户对市场的整体看法、实际尝试及自述发现     |

提炼原则是允许的。例如“先试两周再决定报长期课”可以概括为学习投入上倾向先验证是否适合；公共模块复用的选择可以支持有范围的架构取舍。单次推导不能写成所有场景中的既定习惯，更不能推断人格和动机。

实际经历不必有成功结果或教训。计划尝试不能写成已经经历，助手完成的工作不能写成用户亲身实践。用户看法应保留主体；不能因为出现于投资讨论就推断实盘年限、投资能力或收益。

## 提取链路

1. **读取来源。** 从 Pi 活跃分支和明确上下文编辑构建快照，用消息指纹识别新增内容。原始用户 ID 与文本保留；内容较长时分段。
2. **发现候选。** 每段使用新的 Pi AgentSession，只暴露结果提交工具。候选需引用允许的用户消息。旧记录只帮助去重，不能证明新事实。
3. **程序检查。** 校验结构、原话逐字匹配、消息权限、明确纠正与证据日期、重复内容，以及明显的任务/虚构细节。坏候选逐条过滤并计数。
4. **独立复核。** 新会话只把用户消息作为会话证据，审查每个候选的个人价值、忠实程度、范围、确定性和重复。复核须提交个人价值类别、原话和具体未来用途。
5. **决定接受。** 每个候选必须且只能有一个 review。保留决定必须引用该候选已验证的原话，说明独立于当前实施任务的用途。缺乏个人意义、证据不全或无法判断时丢弃。
6. **正式写入。** 整个来源分析结束后，worker 再逐条提交通过检查的候选。store 在锁内重新检查启用状态、重复与版本。仅当扫描和写入完成后记录 checkpoint。

即时收录、历史提取和 Library 整理共享一份个人价值规则。独立复核是历史提取的额外步骤；即时工具不会在每次写入时额外调用一次复核模型。

## 结构化提交与失败处理

模型通过 `submit_memory_result` 工具参数提交候选或 review，不把自然语言回答当 JSON 解析，也不把“没有合法输出”当成“没有记忆”。TypeBox schema 检查字段；提取工具约束当前可引用的 ID；复核工具约束条数和 index 范围，程序再检查不重复。

每个阶段使用全新会话，工具错误可以反馈给模型修正；每阶段最多处理三次模型回答。纯文本回答最多提示一次重新提交。provider 自身的网络重试与这一上限分开。取消、超出纠错次数或批次无效时保留 checkpoint，允许重试。

源 ID 不合法、逐字引用不匹配或价值检查不通过的单条候选不会保存，也不会拖垮其余合法候选。整批结构不合法或复核漏项不允许冒充扫描完成。一个来源可能合法地保存零条记忆。

## Library 整理

**Organize all memories / Ctrl+O** 把整个记忆库交给当前 Pi 模型，提出重复合并、分类与表述整理方案。

每个原始 ID 必须且只能出现在一个结果组里，省略不是删除。相同事实的同义表达可以合并；不同经历、冲突观点、不同时间和适用条件应保持区分。程序自动保留合并组的全部原话与日期，不让模型重造引文。

预览展示前后内容、合并数和整理理由。用户选择 **Apply organization** 后，store 核对完整快照的 ID 和版本，并在一次事务中发布。期间有新增、编辑或删除会拒绝旧方案，不发生部分覆盖。取消分析或预览不会写入。整理允许在自动记忆 Off 时手动使用。

当前整理使用一次完整上下文；如果库大小超出当前模型预算，会要求选择更大上下文的模型，不静默截断记忆。模型整理仍需要人工阅读预览，尤其是不同条件或观点变化。

## 两层验证

**离线回归**使用合成数据和本地模型夹具，随 `npm run verify` 执行，验证授权、来源、格式、重复、复核覆盖、取消、checkpoint、并发和安装包运行。这些测试证明控制流程，不证明模型理解总是正确。

**真实模型质量评估**使用公开合成案例，涵盖六类以上生活与工作场景，分别检查任务排除和个人内容保留：

```sh
npm run evaluate:quality -- <provider> <model-id>
```

该命令使用当前 Pi 凭据，会消耗模型额度。会话和评估报告写入临时目录，既不读取真实记忆库，也不应用候选。输出逐例结果、项目杂项排除数、个人内容保留数和报告位置。案例包括粘贴材料与助手推断，避免只测试理想输入。

通过合成案例只能说明该模型在本次案例中的表现；不能作为任意真实对话的准确率。应结合实际错误持续完善案例，并通过 **Original words** 复查重要记忆。
