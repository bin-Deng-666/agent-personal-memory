M Agent Personal Memory
PI EXTENSION · TECHNICAL SHARE

让跨对话的个人信息，真正参与下一次回复

这个插件的出发点，是让分散在不同对话里的个人信息能够持续积累，并在后续对话中真正发挥作用。符合条件的沟通和合作习惯会进入模型上下文，影响它的回复方式，让日常交流更个性化；背景、经历、目标和想法则在用户提出相关问题时按需检索，交给能力足够好的模型，用于形成更贴合实际的短期行动和中期建议。

01 / WHY

问题不在于“记住更多”，而在于记住什么

同一个人会在许多对话里反复提到自己的限制、选择、偏好和正在探索的方向。单次对话可以理解这些信息，但下一次对话通常不会自动拥有完整背景。

核心判断

一条信息只有在当前任务结束后仍然有助于理解用户，或帮助模型给出更合适的建议时，才值得进入个人记忆。项目需求、排错进度、安装方式和一次性的格式要求，不因为被说了很多次就自动变成个人偏好。

跨对话积累

把分散在不同会话中的个人上下文保留下来，并在后续需要时找到原始用户消息。记录包括正文、类别、适用范围、确定性、标签和原始引文。

保持边界

“这次短一点”是当前请求；“以后讨论方案先给结论再解释理由”才可能是稳定的合作习惯。一次情绪也只能按一次经历和当时感受处理，不能推导成人格判断。

02 / TWO USES

两种信息路径，对应两种不同用途

插件没有把所有记忆一股脑塞进每次请求。它把适合持续影响表达方式的合作习惯，与需要结合当前问题判断的个人信息分开处理。

Path A · Context

习惯进入模型上下文，让回复更个性化

符合条件、确定性足够高的“稳定偏好”会作为合作上下文加载到普通对话中，例如用户希望回答的结构、解释方式或协作习惯。

  • 影响模型如何回答，而不是替模型决定回答什么。
  • 普通对话只加载合作习惯，控制上下文规模。
  • 新请求优先；旧习惯不应覆盖用户当前明确说法。
Path B · Advice

其他个人信息按需检索，支持阶段建议

背景、经历、目标、想法以及相关偏好，在 Advice 问题中按主题检索。模型需要结合原话，形成当前问题下的短期行动或中期比较。

  • 短期：下一步安排、优先级、两周行动和调整条件。
  • 中期：阶段方向、三个月尝试、投入条件和复盘点。
  • 不相关的记录不应为了“个性化”而强行使用。
03 / WORKFLOW

从用户原话，到可以复查的建议上下文

模型负责理解个人价值和问题相关性，程序负责证据、版本、重复和写入状态等明确约束。两者配合，尽量减少“把项目事实误记成个人信息”的情况。

1

发现信息

从当前对话或 Pi 历史会话中发现可能有长期价值的个人内容。

2

核对原话

要求候选记录引用确切的用户消息，助手分析不能充当个人事实证据。

3

判断价值

检查跨任务可用性、时间、条件、确定性、类别和语义重复。

4

本地保存

按类别保存正文、来源和版本，使用锁与事务日志处理并发和恢复。

5

按需使用

习惯进入普通上下文；其他记录在 Advice 中按问题检索并对照来源。

类别 保存内容 后续用途
个人背景 持续的责任、环境和现实约束 判断某个安排是否可行
个人经历 重要事件、当时选择、自述感受及影响 理解类似选择中的具体经验
目标与方向 认真投入或正在探索的方向 判断当前行动是否服务阶段目标
观点与想法 值得继续讨论的认识和原则 理解用户看待问题的依据
稳定偏好 明确跨对话适用的合作习惯和取舍 调整回答方式与方案呈现
04 / EXAMPLES

短期行动与中期建议，应该怎么问

示例问题 · 非真实私人记录
Short term · 接下来两周

把下一步安排到可以执行

结合我最近提到的时间限制和当前目标，帮我安排接下来两周最值得做的三件事。说明每件事依据哪些信息、最小行动是什么，以及什么情况下应该调整。

适合：近期取舍、学习安排、下一步行动

模型应该给出优先级、最小行动和调整条件；如果时间预算可能已经变化，应当先询问，而不是直接沿用旧记录。

Medium term · 未来三个月

比较方向，并保留探索状态

结合我过去提到的目标、投入条件和相关经历，帮我比较未来三个月的两个方向。列出各自的依据、需要补充的信息，并给出一个可以阶段性复盘的尝试方案。

适合：方向探索、阶段目标、投入安排

“正在考虑”不应被改写成“已经决定”。模型需要把事实、假设和建议分开，并提供可以调整的尝试方式。

建议质量的前提

记忆只能补充上下文，不能替代判断。模型需要能够区分用户原话与自己的推断，保留时间和条件，在证据不足时追问。模型能力越好，跨对话上下文越有机会转化为实际可用的建议；模型能力不足时，记忆也可能让错误的推断看起来更有依据。

05 / IMPLEMENTATION

技术实现：Pi 入口、本地记录、独立复核

Pi 集成：一个入口，三类使用方式

扩展使用 Pi 已配置的模型和凭据，提供 memory_search、memory_write 和 /personal-memory。面板包含 Library、Extraction、Advice；Tab 可以切换 On/Off，关闭后阻止自动写入和新的检索，并请求取消历史提取。

历史提取：extract 和 review 分开进行

历史会话由独立后台任务处理，先提取候选，再在新的模型上下文中复核候选的个人价值、原意、时间、条件、确定性和重复情况。任务支持查看进度、取消和重试；没有符合要求的新内容时，保存零条也是有效结果。

检索：先用轻量排序，保持系统可理解

当前实现将英文词和中文相邻双字作为检索项，过滤常见泛词，再按标题、标签、适用范围和正文命中加权排序。它不依赖向量数据库，适合先验证实际需求；如果日后出现稳定的语义漏检，再根据案例决定是否升级。

存储：本地明文，但保留可追溯和并发控制

默认记忆库位于 ~/.pi/agent/memory/。记录按五类 JSON 文件保存，包含原始引文和版本；写入使用跨进程锁、原子替换与事务日志恢复。扩展没有遥测或托管后端，但必要的上下文和记录仍会发送给 Pi 当前配置的模型提供方。

06 / SCOPE

偏个人的对话，可能更适合这个方向

这个项目更适合学习安排、职业探索、阶段复盘、想法整理和持续的沟通协作。这些问题往往依赖跨会话的背景和条件，也适合在一段时间后重新讨论。

适合 个人阶段性问题

在自己的设备上，选择合适的模型服务，持续讨论目标、经历、限制和下一步。这类场景需要长期上下文，也需要用户不断修正已经变化的情况。

需要判断 外部模型与个人信息

外网环境中的个人使用场景可能更方便，但“更合适”取决于模型质量、服务政策和你对个人信息发送方式的接受程度。本地保存不代表模型请求完全离线。

07 / USAGE

如何安装和使用

Pi 1.2.0 · Node.js 22+

插件安装后由 Pi 直接加载 TypeScript，不需要单独的账号、记忆服务或构建步骤。个人记忆保存在扩展源码之外，更新插件不会自动删除已有记录。

Step 01 · Install

安装并重新加载 Pi

在终端执行安装命令，然后重新加载或重启 Pi。依赖由 Pi 管理，扩展使用 Pi 当前配置的模型和凭据。 

pi install git:github.com/bin-Deng-666/agent-personal-memory
/reload
Step 02 · Open

打开个人记忆面板

在 Pi 对话中输入命令。面板由本地扩展直接打开，不需要先等待一次模型请求。 

/personal-memory
入口 做什么 适合什么时候使用
Library 搜索、查看、编辑、对照 Original words 或删除记忆 检查模型保存的内容是否准确，确认分类、范围和原话
Extraction 浏览 Pi 历史会话，提取并复核其中有个人价值的信息 补充过去对话中的背景、经历、目标、想法和稳定偏好
Advice 输入问题，按问题检索相关记忆并回到主对话获得建议 讨论近期行动、阶段选择、学习安排或中期方向
Tab 切换 Personal Memory On / Off 暂时停止自动写入、检索和正在运行的历史提取

建议的第一次使用方式

  1. 先正常进行几次偏个人的对话，让插件只保存有跨任务价值的信息。
  2. 打开 Library，查看分类、正文和 Original words，删除不准确或不该保存的内容。
  3. 需要规划时打开 Advice，明确写出时间范围、当前目标和希望比较的选项。

更新与卸载

更新或移除扩展不会自动删除个人记忆。需要彻底清理数据时，还要单独处理记忆库、Pi 会话和备份。 

pi update git:github.com/bin-Deng-666/agent-personal-memory
pi remove git:github.com/bin-Deng-666/agent-personal-memory
